## Bugs / correctness

- **Medium — zero-length contig crashes the rule.** `maf_to_sites.py:559`
  `mmap.mmap(fileno, contig_len, ACCESS_READ)` raises `ValueError: cannot mmap an
  empty file` when `contig_len == 0` (empty reference record that is in the MAF
  intersection or explicitly listed in `contigs:`). `summary_report.py` guards
  zero-length contigs, so the design intends to tolerate them but the caller
  doesn't. **Fix:** guard `if contig_len == 0:` before the sample loop and emit
  empty VCF/BED/summary (retained=masked=0), skipping the mmap.

- **Low — leading insertion doesn't flag the following ref base as indel-adjacent.**
  `maf_to_sites.py:350-356`. In the `ref_char == "-"` branch,
  `mark_next_ref_adjacent = True` is set only inside `if prev_ref_idx is not None`,
  so an insertion before the first ref base of a block never flags the next base
  (the symmetric deletion case always does, line 373). Only matters with
  `--mask-indel-adjacent-snps` (default off). **Fix:** set the flag unconditionally
  in the `sample_char != "-"` branch.

- **Low — "Unaligned" genome-overview segment is always empty.**
  `summary_report.py:406-430`. `unaligned = max(length - all_sites - masked_total, 0)`
  is always 0 because the caller enforces `retained + masked == length`. The
  third stacked-bar category and legend entry are dead; "no alignment" bp is
  already inside `masked_total` (`masked_no_alignment`). Cosmetic. **Fix:** drop
  the segment or base it on `masked_no_alignment` specifically.

- **Low — soft-masked (lowercase) bases are silently treated as valid.**
  Both reference and MAF text are `.upper()`-ed, so repeat-masked `acgt` become
  valid ACGT calls; only `N`/non-ACGT is masked. Likely intentional (changelog:
  only N is missing), but there's no option to mask soft-masked regions. Confirm
  against intent.

- **Low — normalization collision aborts the split with no override.**
  `split_maf_by_contig.py:45-50`. If both e.g. `chr1` and `1` survive resolution,
  the split raises `ValueError: Ambiguous normalized contig`. Defensible, but
  turns a resolvable naming quirk into a hard failure. Consider exact-name-first
  routing.

**Verified correct** (traced, no action): `--maf-paths` parsing + Snakefile
`shlex.quote` of `SAMPLE=PATH` and sample names (spaces flow through; chunk path
matches written filename); minus-strand own-genome coordinate mapping
(`src_size - start - 1 - offset`); `QualityMask.is_low` half-open bisect + BED
0-based coords; `IntervalBuilder.add` merging (indices strictly increasing);
the coverage invariant (each index hits exactly one branch); `with_suffix` for
multi-dot contigs; `simulate_msprime_indels.py` srcSize fix (ref row = ref
length, sample row = realized length — both consistent with the FASTAs);
`summary_report.py` GT parsing, 1-based-VCF vs 0-based-BED window indexing,
zero/absent-contig guards, and REF pseudo-sample exclusion.

## Efficiency / performance

Scale: contig length `L` up to ~2e9, `S` = dozens of samples, ~25 contigs. The
`L×S` pure-Python paths dominate wall time.

- **High — adjacent-indel work runs unconditionally.** `maf_to_sites.py:331,
  349-373, 563-564`. `load_sample_calls` allocates a second contig-length
  `bytearray` per sample and does per-column indel bookkeeping, then `main`
  OR-merges all of them — but `adjacent_indel_flags` is only read under
  `if args.mask_indel_adjacent_snps`, **default False**. Entirely wasted by
  default. **Fix:** pass the flag into `load_sample_calls`, skip the array +
  branches + merge when off.

- **High — O(L×S) pure-Python OR-merge.** `maf_to_sites.py:563-564`
  (`for i in range(...): adjacent_indel_flags[i] |= ...`) — up to ~6e10 indexed
  bytearray ops. Even when the feature is on, vectorize with
  `np.frombuffer(..., np.uint8)` bitwise-or; when off, skip entirely (above).

- **High — per-sample missing-BED pass re-scans the contig per sample in Python.**
  `maf_to_sites.py:682-688`. Another O(L×S) loop over mmap bytes, runs regardless
  of config. **Fix:** `np.frombuffer(calls, np.uint8)`, `np.isin(arr, MISSING_CODES)`,
  derive runs via `np.flatnonzero(np.diff(...))` for vectorized BED emission.

- **High (structural) — main all-sites loop is O(L×S) with per-position allocs.**
  `maf_to_sites.py:588-672`. Per reference base it loops all sample mmaps and, per
  non-masked site, builds fresh `call_codes`/`alleles`/`allele_set` + `sorted()`,
  though most sites are invariant. Dominant CPU cost. **Fix (larger):** chunked
  numpy classification over the stacked uint8 arrays; drop to Python only to
  format the (rare) variant/invariant VCF rows.

- **Medium — `threads: 2` but the script is single-threaded.** `Snakefile:339`.
  Wastes a core / halves concurrent contig jobs. Set `threads: 1` or actually
  parallelize per-sample `load_sample_calls`.

- **Medium — split writes uncompressed chunks even from `.maf.gz`.**
  `split_maf_by_contig.py:55` (+ `Snakefile:323`). Output is hard-coded
  `{contig}.maf`, so `.maf.gz` inputs decompress to a full (uncompressed) copy of
  the MAF corpus under `results/maf_by_contig/`. **Fix/consider:** write
  `{contig}.maf.gz`, and/or mark the chunk dir `temp()` so Snakemake reclaims it
  after `direct_maf_sites`. (Split itself streams correctly — confirmed a net win
  vs ~25 full rescans per sample.)

- **Low — `summary_report.py:119-130` splits every genotype cell on `:`** though
  FORMAT is always bare `GT`. Harmless but pure overhead on multi-GB VCFs. Longer
  term, have `maf_to_sites` emit per-sample counters into `.site_summary.tsv` so
  the report never re-scans the VCFs.

- **Low — `simulate_msprime_indels.py`** `apply_indel_events` uses O(n·k)
  slice-insert/delete, but it is **not** dead (it's unit-tested; just unused by
  `main`), so it was left alone. `summarize_reference_overlaps` builds position
  `set`s (fine at sim scale). The recent `proposed_by_sample` bucketing correctly
  removed an O(events×samples) filter.
